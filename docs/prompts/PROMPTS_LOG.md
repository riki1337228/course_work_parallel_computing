| Параметр | Значення |
|---|---|
| Інструмент | Claude Code (Anthropic), модель Claude Opus 5.5, розширення для VS Code |

## Як використовувався ШІ

Окремих промптів для кожного компонента **не надсилалося**. Розробку виконано за одним детальним
промптом-специфікацією (повний текст — у [master_prompt.md](master_prompt.md)) з короткими доповненнями.
Розділи цього промпту виконували роль окремих промптів для архітектури, Thread Pool, інвертованого індексу,
інтеграції Ollama, тестування та аналізу benchmark (таблиця нижче).

Після завершення розробки студент надіслав ще кілька промптів: два питання про запуск і перевірку,
промпт на повний аудит (повний текст — у [audit_prompt.md](audit_prompt.md)), питання про розташування
записки та промпт на виправлення знайдених проблем. Нижче наведено **всі** промпти в хронологічному
порядку. Технічні рішення в межах кожного промпту ШІ ухвалював самостійно на основі результатів тестів
і перевірок.

## Виправлення, які ШІ зробив за результатами перевірок

Ці дефекти знайдено під час фактичного запуску, а не теоретично.

Під час розробки (22.11):

1. Логи сервера не з'являлися в `docker compose logs`, бо stdout буферизувався. Додано flush кожного рядка логу.
2. CLI не підключався до `localhost` у контейнері: ім'я резолвилося в IPv6 `::1`, а сервер слухає лише IPv4. Тепер `localhost` замінюється на `127.0.0.1`.
3. Приклад `car` у промпті змушував модель копіювати приклад для запиту `car`. Приклад замінено на нейтральний (`doctor`).
4. Після зупинки Ollama кеш доступності кілька секунд віддавав застаріле `true`. Оновлення кешу стало серіалізованим, після тайм-ауту виконується повторна перевірка, тайм-аут генерації зменшено з 60 до 30 с.
5. CSS: атрибут `hidden` перекривався правилом `display:flex`.
6. Для запиту лише зі стоп-слів (`the and of`) модель «вигадувала» терміни, і пошук повертав 20 000 нерелевантних документів. Такі запити більше не надсилаються в LLM.
7. ThreadSanitizer (GCC 13) падав через високу ентропію ASLR. Тести під TSan запускаються з `setarch -R`.

За результатами аудиту (23–24.11):

8. **LLM блокувала звичайний пошук** під навантаженням (23 с очікування): введено окремий `llmPool` (bulkhead), обмежену чергу з миттєвим fallback і бюджет часу від надходження запиту. Після виправлення пошук без LLM під тим самим навантаженням відповідає за 5–17 мс.
9. Фонова перевірка доступності (пункт 8) спершу погіршила випадок «Ollama щойно зупинили» до 32 с. Виправлено паралельною перевіркою під час очікування: тепер ≤ 2 с.
10. Датасет 1,998 ГіБ збільшено до 2,049 ГіБ (> 2 ГБ за будь-якого тлумачення).
11. `mode` став обов'язковим для REST (як у контракті), `/api/health` повертає рівно поля контракту, 405 повертає JSON.
12. Від'ємні значення змінних середовища (`REQUEST_THREADS=-1`) валили сервер. Тепер вони ігноруються з попередженням.
13. Зміст DOCX-записки не відповідав сторінкам у MS Word. Зміст тепер рахується за пагінацією Word, порожню сторінку прибрано.
