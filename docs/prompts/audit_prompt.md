# 1. Перевірка відповідності вимогам

Перевір кожну вимогу:

### Мова програмування
- Backend реалізований на C++, Java або C#.
- Якщо використовується C++, перевір відповідність стандарту C++20, якщо він заявлений у проєкті.
- Переконайся, що основна логіка пошукової системи реалізована саме на дозволеній мові.

### Docker та Docker Compose
- Чи запускається система командою `docker compose up`?
- Чи є окремий сервіс пошукового сервера?
- Чи є окремий сервіс Ollama?
- Чи правильно налаштовані мережі, volumes, залежності та healthchecks?
- Чи можна запустити проєкт після свіжого клонування репозиторію без ручного встановлення залежностей на хостову систему?
- Чи відбувається компіляція Backend усередині Docker, якщо локального компілятора немає?
- Чи правильно запускаються всі контейнери?

### Інвертований індекс
- Чи реалізована власна структура даних inverted index?
- Чи правильно вона зберігає відповідність між термінами та документами?
- Чи підтримує одночасний доступ із кількох потоків?
- Чи захищені спільні дані від race condition?
- Чи немає deadlock?
- Чи правильно відбувається індексація документів?
- Чи є можливість повторно побудувати індекс?

### Thread Pool
- Чи реалізований власний Thread Pool, а не просто використовується готова бібліотека?
- Чи є черга завдань?
- Чи є робочі потоки?
- Чи коректно працюють mutex, condition_variable та інші механізми синхронізації?
- Чи правильно завершується робота потоків?
- Чи можна змінювати кількість потоків через параметр threads?
- Чи дійсно різна кількість потоків впливає на виконання індексації?

### REST API

Перевір наявність і відповідність контракту:

1. GET `/api/health`
2. POST `/api/index`
3. POST `/api/search`
4. GET `/api/stats`

Перевір:
- HTTP-методи;
- URL;
- JSON-запити;
- JSON-відповіді;
- назви полів;
- типи даних;
- обробку некоректних запитів;
- HTTP status codes.

Порівняй реалізацію з контрактом у силабусі. Не змінюй контракт довільно.

### Ollama та LLM
- Чи дійсно система звертається до локального Ollama API `/api/generate`?
- Чи передається запит до мовної моделі?
- Чи отримує система відповідь?
- Чи виконується query expansion?
- Чи використовуються отримані ключові слова та синоніми в реальному пошуку?
- Чи правильно обробляється ситуація, коли Ollama недоступна?
- Чи є fallback на keyword search?

Не допускається імітація роботи LLM без реального звернення до Ollama.

### WebSocket
Перевір endpoint `/ws/search`.

Повинні передаватися окремі повідомлення:
- `query_expansion`;
- `keyword_search`;
- `done`.

Перевір JSON-структуру повідомлень, поля `stage` та `data`, послідовність етапів і коректну обробку помилок.

Перевір:

- формат файлів;
